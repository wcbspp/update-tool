# update-tool

把「批量增量更新 SQL」管住的执行工具：脚本集中管理、执行前预检、整段事务执行、出错整体回滚。

Go 单文件服务 + 内嵌网页，零运行时依赖：Windows 双击 `exe` 即用，macOS / Linux 直接运行单个二进制。

> 内置默认名称是 `update-tool`，设置里可以改成任何名字（界面标题、说明页、启动提示都会跟着变）。
> 本仓库示例沿用了「批次表 → 正式表」的目录更新场景，工具本身不绑定具体业务。

---

## 它解决什么问题

批量更新 SQL 常见的坑：脚本写错一行、跑错批次、跑到一半失败留下半套数据、重复执行。

这个工具把三件事固定下来：

1. **执行前先预检**：主键会不会冲突、源表有没有数据、会不会整表更新、条件是否重叠、版本号对不对
2. **整段事务执行**：所有语句在一个事务里顺序执行，任一条失败**整体回滚**，不会改一半
3. **留下执行日志**：什么时候、跑了哪份脚本、几条语句、耗时、失败在第几条

## 主要功能

### 预检（只读，不改数据）

| 检查项 | 说明 |
|---|---|
| 主键冲突 | 目标表已存在相同主键时提示（通常意味着这批已跑过） |
| 源表为空 | 批次表没数据时提示该语句不会命中 |
| 没有 WHERE 条件 | UPDATE / DELETE 缺 WHERE 时直接报错 |
| SET 列不存在 | 要更新的列在目标表里找不到 |
| 列数不一致 | `INSERT ... SELECT` 两表列数对不上 |
| 预计影响行数 | 多表 UPDATE 按条件实际统计（最多 30 万行）；单表 UPDATE 按执行计划估算 |
| 索引使用情况 | 统计查询实际走了哪个索引；没有可用索引时提示「全表扫」 |
| 同一张表被多条语句更新 | 比较各语句的 WHERE：重叠 / 互不重叠 / 无法自动比对 |
| 非事务引擎 | 目标表不是 InnoDB 时直接报错：写入回滚不了 |
| 数据版本 | 读批次表的版本字段，确认跑的是哪一批 |
| 未提交事务 | 提示库上存在长事务 |

预检只读这一点有自动化验证：用**只授予 SELECT 的账号**跑完整预检，并把相关表整份 dump 前后比对。

### 执行

- 单事务、顺序执行、失败即回滚
- 拒绝 DDL（`CREATE` / `ALTER` / `DROP` / `TRUNCATE`）——DDL 隐式提交，回滚保不住
- 拒绝脚本内自带 `COMMIT` / `ROLLBACK`——事务由工具统一管理
- 同一时间只允许一个执行任务，重复点击返回「已有脚本正在执行」

### 界面

- 左侧：数据源 → 文件夹（可嵌套）→ 脚本
- 中间：语法高亮编辑器，行号、美化、语法校验（`EXPLAIN`）
- 下方：结果区默认折叠，只显示结论；展开看完整 SQL 与提醒明细；点提醒可跳到对应语句

### 配置

- 数据源口令 AES-256-GCM 加密落盘；老版本明文配置自动迁移
- 配置可整体导出/导入（加密文件，可选是否带口令）
- 顶部显示名称可自定义，默认 `update-tool`

## 支持范围

| 环境 | 状态 |
|---|---|
| MySQL 8.4 | 自动化测试全绿（见下） |
| MariaDB 11.6 | 自动化测试全绿 |
| MySQL 5.7 / 5.6 | 语法与功能兼容，生产在用；未纳入自动化矩阵 |
| 分库分表中间件（DRDS / PolarDB-X 等） | 可用，但 `information_schema` 常受限：部分预检项会降级成「无法判断」，不做猜测 |

已知限制：

- 跨库写入（`INSERT INTO 其他库.t`）只对引擎检查按目标库判定，列数/主键等仍按连接库解析
- 分片中间件下，`CONCAT` 等表达式写在连接条件里可能无法下推；建议预先把值落到真实列再等值连接
- 30 万行以上只报下限，不做全量计数

## 快速开始

```bash
# macOS / Linux
./medupdate

# Windows
medupdate.exe
```

启动后自动打开浏览器，默认只监听 `127.0.0.1:8787`（设置里可切到「允许局域网」）。

第一次使用：

1. 右上「设置」配置新文件夹是否默认开启预检、界面名称
2. 左侧「＋」新建数据源，填地址、端口、账号、口令、库名
3. 数据源上「＋」建文件夹，文件夹里建脚本，粘贴 SQL
4. 选脚本 → 「数据预检」→ 看清结论 → 「执行」

## 测试

```bash
cd goapp

# 只跑单元测试（无外部依赖）
go test ./...

# 全量：需要测试库，用例会建表/删表
MYSQL_TEST_DSN='root:口令@tcp(127.0.0.1:3306)/medupdate_test' go test ./...
```

安全闸：`smoke_test.go` 会解析 DSN，**库名不以 `_test` 结尾直接拒绝运行**，避免误连生产库。

当前结果（2026-10-30）：

| 环境 | 用例 | 结果 |
|---|---|---|
| MySQL 8.4.13 | 135 个用例函数 | 132 通过 / 3 跳过 / 0 失败 |
| MariaDB 11.6.2 | 同上 | 132 通过 / 3 跳过 / 0 失败 |
| `go test -race` | 同上 | 0 数据竞争 |

覆盖重点：

- **预检零写入**：只读账号跑通 + 全表 dump 前后逐行比对
- **执行完整性**：五条语句逐条回查；失败语句插到每一个位置都要求零残留；驱动禁用 multiStatements
- **配置**：明文迁移、密文损坏拒写、密钥轮换后的可读性
- **接口层**：CRUD、导出导入、`/dl/` 白名单、忙碌锁、日志

测试设计说明见 [`docs/TESTING.md`](docs/TESTING.md)。

## 配置

配置存放在程序同目录的 `data.json`（权限 600）。口令写盘前会用 AES-256-GCM 加密，文本编辑器打开是乱码；
但密钥编译在程序里，**拿到程序的人仍能解开**，所以它只挡「文件被误看/误传」，不是保密存储。
导出配置（设置 → 导出全部配置）同样是加密文件，可选是否带上口令。

### 环境变量

| 变量 | 默认 | 用途 |
|---|---|---|
| `PORT` | `8787` | 监听端口 |
| `HOST` | 由监听范围决定 | 覆盖绑定地址 |
| `APP_NAME` | `update-tool` | 界面显示名称（设置里也能改） |
| `ACCESS_KEY` | 空 | 设置后所有请求需带 `?k=密钥` 或 `X-KEY` 头 |
| `NO_OPEN` | 空 | 设 `1` 则不自动打开浏览器 |
| `SQLC_HOME` | 可执行文件目录 | 数据与日志目录 |

### 每个数据源可单独配的超时

| 字段 | 默认 | 说明 |
|---|---|---|
| 连接超时 | 10 秒 | 建连超时 |
| DQL 超时 | 60 秒 | 查询类语句（含预检统计）；到点由 MySQL 中断 |
| DML 超时 | 1800 秒 | 执行阶段的写入；到点中断并整体回滚；填 0 表示不限 |

网络层读写超时不用单独设置，工具取 `max(DQL, DML) + 60 秒`。

## 构建

```bash
./build.sh
```

产出：

```
release-win/medupdate.exe      Windows amd64
release-mac/medupdate          macOS arm64
release-linux/medupdate        Linux amd64
dist/update-tool.app           macOS 应用包（自动同步新二进制并重签名）
```

需要 Go 1.21+。构建使用 `CGO_ENABLED=0`、`-trimpath -ldflags "-s -w"`，产物约 8 MB，无外部依赖。

自建自动更新时注入分发地址（不设则不检查更新）：

```bash
UPDATE_URL='https://你的地址/' ./build.sh
```
