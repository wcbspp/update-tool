# update-tool

内部工具，用来管理、预检并执行业务目录（药品 / 诊疗项目 / 医用耗材）的增量更新 SQL。

Go 单文件服务 + 内嵌网页，零运行时依赖：Windows 双击 `exe` 即用，macOS / Linux 直接运行单个二进制。

---

## 它解决什么问题

业务目录做增量更新时，常见的坑是：脚本写错一行、跑错批次、跑到一半失败留下半套数据。

这个工具把三件事固定下来：

1. **执行前先预检**：主键会不会冲突、源表有没有数据、会不会整表更新、条件是否重叠、版本号对不对
2. **整段事务执行**：所有语句在一个事务里顺序执行，任一条失败**整体回滚**，不会改一半
3. **留下执行日志**：谁、什么时候、跑了哪份脚本、几行、耗时、失败在第几条

## 主要功能

### 预检（只读，不改数据）

| 检查项 | 说明 |
|---|---|
| 主键冲突 | 目标表已存在相同主键时提示（通常意味着这批已跑过） |
| 源表为空 | 批次表没数据时提示该语句不会命中 |
| 没有 WHERE 条件 | UPDATE / DELETE 缺 WHERE 时直接报错 |
| SET 列不存在 | 要更新的列在目标表里找不到 |
| 列数不一致 | `INSERT ... SELECT` 两表列数对不上 |
| 预计影响行数 | 多表 UPDATE 按条件实际统计（最多 30 万行）；单表 UPDATE 按执行计划估算；超过显示 `≥ 300000` |
| 索引使用情况 | 统计查询实际走了哪个索引；没有可用索引时提示「全表扫」 |
| 同一张表被多条语句更新 | 比较各语句的 WHERE：条件重叠 / 互不重叠 / 无法自动比对 |
| 判重键可空 | 唯一键含 NULL 列时提示：NULL 不参与唯一性比较，重复可能漏检 |
| 数据版本 | 读批次表的 `CRTER_ID`，确认跑的是哪一批 |
| 未提交事务 | 提示库上存在长事务 |

### 执行

- 单事务、顺序执行、失败即回滚
- 拒绝 DDL（`CREATE` / `ALTER` / `DROP` / `TRUNCATE`）——DDL 隐式提交，回滚保不住
- 拒绝脚本内自带 `COMMIT` / `ROLLBACK`——事务由工具统一管理
- 同一时间只允许一个执行任务，重复点击返回「已有脚本正在执行」

### 界面

- 左侧：数据源 → 文件夹（可嵌套）→ 脚本
- 中间：语法高亮编辑器，行号、美化、语法校验（`EXPLAIN`）
- 下方：结果区默认折叠，只显示结论；展开看完整 SQL 与提醒明细；点提醒可跳到对应语句

## 快速开始

### 直接运行

```bash
# macOS / Linux
./medupdate

# Windows
medupdate.exe
```

启动后自动打开浏览器，默认只监听 `127.0.0.1:8787`（设置里可切到「允许局域网」）。

### 第一次使用

1. 右上「设置」里可配置新文件夹是否默认开启预检
2. 左侧「＋」新建数据源，填地址、端口、账号、口令、库名
3. 数据源上「＋」建文件夹，文件夹里建脚本，粘贴 SQL
4. 选脚本 → 「数据预检」→ 看清楚结论 → 「执行」

## 配置

配置存放在程序同目录的 `data.json`（权限 600）。口令写盘前会用 AES-256-GCM 加密，文本编辑器打开是乱码；
但密钥编译在程序里，**拿到程序的人仍能解开**，所以它只挡「文件被误看/误传」，不是保密存储。
导出配置（设置 → 导出全部配置）同样是加密文件，可选是否带上口令。

### 环境变量

| 变量 | 默认 | 用途 |
|---|---|---|
| `PORT` | `8787` | 监听端口 |
| 监听范围 | 本机 | 在「设置」里切换；`settings.listenMode=all` 时监听 `0.0.0.0` |
| `ACCESS_KEY` | 空 | 设置后所有请求需带 `?k=密钥` 或 `X-KEY` 头 |
| `NO_OPEN` | 空 | 设 `1` 则不自动打开浏览器 |
| `SQLC_HOME` | 可执行文件目录 | 数据与日志目录 |

### 每个数据源可单独配的超时

| 字段 | 默认 | 说明 |
|---|---|---|
| 连接超时 | 10 秒 | 建连超时 |
| DQL 超时 | 60 秒 | 查询类语句（含预检统计）；到点由 MySQL 中断 |
| DML 超时 | 1800 秒 | 执行阶段的写入；到点中断并整体回滚；填 0 表示不限 |

网络层读写超时不用单独设置，工具取 `max(DQL, DML) + 60 秒`（DML 不限时给 2 小时）。

## 构建

```bash
./build.sh
```

产出：

```
release-win/medupdate.exe      Windows amd64
release-mac/medupdate          macOS arm64
release-linux/medupdate        Linux amd64
dist/update-tool.app        macOS 应用包（自动同步新二进制并重签名）
```

需要 Go 1.21+。构建使用 `CGO_ENABLED=0`、`-trimpath -ldflags "-s -w"`，产物约 7 MB，无外部依赖。

## 测试

```bash
cd goapp

# 单元测试
go test ./...

# 真库集成测试（事务回滚 / 预检分支）
MYSQL_TEST_DSN='root:口令@tcp(127.0.0.1:3306)/medupdate_test' go test -run 'TestPreflight|TestRunStatements' -v

# 大表场景测试（默认 300 万行，可用 MYSQL_PERF_ROWS 调整）
MYSQL_PERF_DSN='root:口令@tcp(127.0.0.1:3306)/medupdate_perf' \
MYSQL_PERF_ROWS=10000000 go test -run TestPerfScenarios -v -timeout 50m
```

未设置 DSN 时相关测试自动跳过，不会误连生产库。测试用的库由测试自己建表、自己删表。

## 安全边界

- **不做鉴权**（内网工具，部署时按需设置 `ACCESS_KEY` 或只监听 `127.0.0.1`）
- 预检是**只读**的，不改任何数据
- 执行是**单事务**的，失败整体回滚
- 回滚保不住的两件事：自增 ID 跳号、触发器里的外部副作用
- 工具能回滚“执行失败”，回滚不了“条件写错”——**更新前请先备份目标表**

改代码前先看 [`docs/PROJECT.md`](docs/PROJECT.md)：里面记了架构决策、预检语义、发版流程、服务器部署细节，以及**踩过的坑**（缩放、datalist、WAF、缓存、单实例接管等）。新会话接手时按那份文档走，别从头猜。

## 已知限制

- 预检的行数统计上限 30 万行，超过显示 `≥ 300000`
- WHERE 里的函数、列比列等复杂条件，冲突判断会标注「无法自动比对」
- 索引判断按 MySQL 最左前缀规则；不满足时提示「缺少可用索引」
- 未做多用户并发设计：同一时间只允许一个执行任务
