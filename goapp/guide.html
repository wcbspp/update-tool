使用说明

update-tool · 本地 / 内网部署

把原来手工执行的一串 SQL 收进一个可复核的操作台，防止手抖——降低连错库、漏改语句、重复执行、条件写错的风险。

能做什么

  • 语法校验：逐条 EXPLAIN，查语法、表和字段是否存在、权限够不够；不改数据
  • 数据预检：主键冲突、源表是否为空、列数是否一致、预计影响行数、本次数据版本
  • 版本号核对：从批次表的版本字段（默认 CRTER_ID，可在脚本设置里改）取值去重，执行前摆出来；不符合设定前缀的值标红
  • 执行：整段 SQL 在一个事务里跑，任一语句失败整体回滚；含 DDL 或 COMMIT / ROLLBACK 直接拒跑
  • 执行日志：每次执行留痕——时间、脚本、数据源、语句数、耗时、成败、失败位置
  • 只读保护：SQL 默认只读，点“编辑”才能改，保存后自动切回只读
  • 分组管理：数据源 → 文件夹 → 脚本；数据源挂在顶层文件夹上，数据预检与版本规则可按文件夹设，单条脚本可单独覆盖

典型用法：批次表 → 正式表

常见形态是「本批次数据先落一张 *_update_* 临时表，核对无误后再并进正式表」：

批次表（本次数据）正式表（线上在用）做法
orders_update_202601orders关旧记录 + 插入新记录
prices_update_202601prices同步调价、停用旧价

表名只是示例，工具不绑定任何具体业务表。

示例：关旧开新

把原记录的结束时间设成新记录开始日期的前一天，新旧时间段首尾相接：

ENDDATE = DATE_SUB(B.BEGNDATE, INTERVAL 1 day)

例：新批次 2026-10-25 生效，旧记录的 ENDDATE 写成 2026-10-24；新记录的 ENDDATE 为 NULL，表示当前有效。

关旧时一般带上 ENDDATE IS NULL OR ENDDATE >= B.BEGNDATE，避免把已经失效的历史记录重复改写。

首次运行

  • Windows：解压前可先右键压缩包 → 属性 → 勾选「解除锁定」，再解压；双击 update-tool.exe。 若弹出「Windows 已保护你的电脑」，点「更多信息」→「仍要运行」——未签名程序的正常提示，不是病毒。
  • macOS：首次打开若提示「无法验证开发者」，右键 → 打开；或终端执行 xattr -d com.apple.quarantine ./medupdate
  • 启动后会自动打开浏览器，地址 http://127.0.0.1:8787/。
  • 升级时直接双击新版本，会自动接管正在运行的旧实例；data.json 配置不受影响。
  • 关于配置文件：data.json 与程序放在同一目录，里面保存数据源、脚本和数据库口令。 口令在写盘前会加密，用文本编辑器打开是乱码，放进网盘或被备份扫描也看不出内容。 但它不是真正的保密：拿到这个程序的人仍然能解开。所以别把程序和这个文件一起交给不相干的人。
  • 换电脑 / 给同事：在设置里点「导出全部配置」，导出文件同样是加密的，对方用本程序导入即可。 导出时可以选择是否带上口令：不带的，对方导入后要自己补录。

使用流程

  1. 左侧选择脚本（脚本所在文件夹已绑定数据源）
  2. 点 数据预检：看主键是否冲突、源表是否有数据、列数是否对得上、预计影响多少行、版本号对不对
  3. 点 执行：确认框里再核对一次版本号与影响行数，确认后提交
  4. 到 执行日志 复核本次结果；有失败会标出是第几条

访问范围与退出

  • 默认只允许本机访问：工具默认监听 127.0.0.1，只有这台电脑能打开； 需要同事访问时，到「设置 → 访问范围」切换到「允许局域网访问」。
  • 局域网访问没有登录验证：开启后同网段任何人都能打开并执行脚本，请确认网络环境可信再开启。
  • 切换访问范围后程序会自动重启（约 2 秒），页面会自动刷新，不需要手动关闭。
  • 退出程序：设置弹窗左下角「退出程序」，二次确认后结束；退出后页面会断开，重新双击程序即可再用。
  • 顶部状态区：绿色圆点表示服务在响应（每 20 秒探活，异常变红），旁边显示当前是「本机」还是「局域网」， 以及已配置的连接数与脚本数。

预检的数字与索引

  • 影响行数是“预计”值：预检按当前数据实际统计，不是估值；但为避免拖慢数据库，最多数到 30 万行，超过会显示 ≥ 300000
  • 预检需要索引支撑：主键冲突比对要按判重列查目标表，如果表上没有合适的索引，会退化成全表扫，工具会直接提示“缺少可用索引”，请先补索引再预检
  • 索引不合适时不会硬跑，只提示；执行功能本身不受影响

超时设置（每个数据源可单独配）

  • 连接超时：默认 10 秒。网络不通时不用干等
  • DQL 超时：默认 60 秒。管查询类语句，包括预检里的统计查询；超了会显示「未计算」而不是报错。 大表（百万行以上）统计可能需要几分钟，这种情况请把 DQL 超时调到 300 秒或更大
  • 多表 UPDATE 的影响行数：按语句条件做有界计数（最多 30 万行）， 超过「预检查询超时」（默认 20 秒）就退回执行计划估算。分片中间件下不了推的连接条件 （例如 ON CONCAT(...)=...）会退化成笛卡尔积，计数会很慢，建议把连接条件改成普通列比较
  • DELETE 影响行数：默认走有界精确计数（最多数 30 万行），数不完或超时才退回执行计划估算， 那时会标「按执行计划估算」
  • 未提交事务：只提示当前库里改了行却没提交的事务；别的库有未提交事务不会打扰你
  • 预检查询超时：默认 20 秒。只管预检里「数行数、查重复、查冲突、估算影响行数」这几条重查询； 到点就降级成「行数统计失败」「按执行计划估算」，不会卡住更新。填 -1 表示不加这条上限，交给 DQL 超时控制
  • DML 超时：默认 1800 秒（30 分钟）。管执行阶段的写入语句，超时会被中断并整体回滚；填 0 表示不限
  • 网络读写超时不用单独设，工具取 DQL、DML 的较大值再留 60 秒余量

安全边界

  • 整段 SQL 在一个事务内执行，失败整体回滚，不会出现“改了一半”
  • 脚本含 DDL（建表 / 改表 / 清空）会被拒绝，请单独在客户端处理——DDL 会隐式提交，回滚保不住
  • 脚本内写 COMMIT / ROLLBACK 同样会被拒绝，事务由工具统一管理
  • 数据预检为只读，不改动任何数据；执行前的确认框不可跳过
  • 自增 ID 会跳号、触发器里的外部副作用无法回滚，这两点由数据库本身决定

术语

  • 批次表：本次待更新的数据表，通常带 _update_ 之类的后缀
  • 目标表：线上正式表，更新后生效的地方
  • 版本字段：一般用 CRTER_ID 这类字段标识批次，可在脚本设置里改
  • 分区/归属字段：如 POOLAREA_NO，具体叫什么由你的业务决定

更新数据前请务必备份

工具能回滚“执行失败”，但回滚不了“条件写错”。更新前请先备份目标表，或确认已存在可用的备份。
